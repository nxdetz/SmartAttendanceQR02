SMART ATTENDANCE QR - WEB APPLICATION
ระบบเช็คชื่อผ่านเว็บไซต์ ด้วย Java Spring Boot + SQLite

เป้าหมายการใช้งาน:
- ผู้ใช้ทั่วไปใช้ Chrome เท่านั้น ไม่ต้องติดตั้ง Java, VS Code หรือ MySQL
- ต้องนำเว็บแอปไปรันบนเครื่อง Server/Cloud หนึ่งเครื่องก่อน
- เครื่องอื่นเปิด URL ของเว็บผ่าน Chrome เพื่อใช้งาน
- กล้องบนเว็บต้องใช้ HTTPS (หรือ localhost) และผู้ใช้ต้องกดอนุญาต Camera

เทคโนโลยี:
Java 17, Spring Boot, SQLite, HTML/CSS/JavaScript
ตัวอ่าน QR ใช้ html5-qrcode จาก CDN จึงต้องมีอินเทอร์เน็ตขณะเปิดหน้าเว็บ

ทดสอบในเครื่อง Server:
1. ติดตั้ง JDK 17 และ Maven บนเครื่อง Server เท่านั้น
2. เปิดโฟลเดอร์นี้ด้วย VS Code หรือ IDE ที่รองรับ Maven
3. เปิด Terminal แล้วรัน: mvn spring-boot:run
4. เปิด Chrome ไปที่ http://localhost:8080
5. บัญชีเริ่มต้น admin / admin123

ใช้จากเครื่องอื่นในเครือข่ายเดียวกัน:
- เปิดพอร์ต 8080 ใน Firewall ของ Server
- ใช้ IP ของ Server เช่น http://192.168.1.20:8080
- หมายเหตุ: Chrome มักไม่อนุญาตกล้องบน HTTP ผ่าน IP เครื่องอื่น
- ถ้าจะสแกนกล้องจากเครื่องอื่น ต้องติดตั้ง HTTPS และ certificate ให้โดเมน/เซิร์ฟเวอร์

การใช้งาน:
1. เพิ่มรายวิชาและอีเมลอาจารย์
2. เพิ่มนักศึกษา
3. ลงทะเบียนนักศึกษาในรายวิชา
4. แท็บ QR Code: พิมพ์หรือดาวน์โหลด QR ประจำตัวของนักศึกษาแต่ละคน (เป็นลิงก์ลับเฉพาะคน)
   ตอนเช็คชื่อ: แท็บเช็คชื่อ > เลือกวิชา > เปิดรับเช็คชื่อ > นักศึกษาสแกน QR ด้วยแอปใดก็ได้ ไม่ต้องล็อกอิน
5. เลือกรายวิชา เปิดกล้อง สแกน QR และยืนยัน
6. ดูรายงานมาเรียน/ขาดเรียน

อีเมลแจ้งเตือน (ไม่บังคับ):
กำหนด environment variables บน Server:
MAIL_HOST=smtp.gmail.com
MAIL_PORT=587
MAIL_USERNAME=บัญชีผู้ส่ง
MAIL_PASSWORD=Google App Password
จากนั้นตั้งค่า MAIL_FROM เพิ่มในระบบ (ถ้าต้องการระบุ From)
และกรอกอีเมลอาจารย์ในข้อมูลรายวิชา
หากไม่ตั้งค่าอีเมล ระบบยังบันทึกการเข้าเรียนได้ แต่อีเมลไม่ถูกส่ง

บัญชีเริ่มต้น:
ADMIN_USERNAME=admin
ADMIN_PASSWORD=admin123
สามารถกำหนด environment variables ก่อนเริ่มครั้งแรกได้
หากสร้างบัญชีในฐานข้อมูลแล้ว การเปลี่ยน env จะไม่เปลี่ยนบัญชีเดิม

ข้อควรทราบ:
- นี่เป็นต้นแบบสำหรับโปรเจกต์นักศึกษา ยังไม่ผ่านการตรวจสอบความปลอดภัยก่อน production
- เปลี่ยนรหัสผ่านเริ่มต้นก่อนเผยแพร่
- เปิด HTTPS ก่อนใช้กล้องจากเครื่องลูกข่าย
- SQLite เหมาะกับงานขนาดเล็ก; หากใช้งานหลายคนพร้อมกันจำนวนมาก ควรใช้ PostgreSQL/MySQL
- QR code เป็นรหัสนักศึกษา ไม่ใช่หลักฐานยืนยันตัวตนที่ป้องกันการส่งต่อได้ จึงควรมีมาตรการป้องกันการเช็คชื่อแทนกัน

การนำขึ้นออนไลน์ด้วย Railway (HTTPS และ URL สำหรับเข้าใช้จากทุกที่):
1. สมัคร Railway และ GitHub ด้วยบัญชีของตนเอง
2. สร้าง GitHub repository ใหม่ แล้วอัปโหลดไฟล์ทั้งหมดในโฟลเดอร์นี้
3. ใน Railway เลือก New Project > Deploy from GitHub Repo แล้วเลือก repository นี้
4. Railway จะตรวจพบ Dockerfile และ build แอป Java ให้
5. ใน Service Settings > Networking ให้สร้าง Public Domain เพื่อได้ URL เว็บไซต์
6. ใน Service > Variables ตั้งค่า ADMIN_USERNAME และ ADMIN_PASSWORD เป็นบัญชีที่คาดเดายาก
7. เพิ่ม Volume ใน Railway แล้วกำหนด Mount Path เป็น /app/data เพื่อเก็บ SQLite ให้คงอยู่หลัง deploy/restart
8. ตั้งค่า DB_PATH=/app/data/attendance.db และ PORT ให้ Railway กำหนดอัตโนมัติ (อย่ากำหนด PORT เป็นค่าคงที่ถ้าแพลตฟอร์มจัดการให้)
9. กด Deploy แล้วเปิด Public Domain ด้วย Chrome
10. ทดสอบเพิ่มวิชา เพิ่มนักศึกษา ลงทะเบียน และสแกน QR โดยอนุญาตกล้อง

ตั้งค่าอีเมล (หากต้องการแจ้งอาจารย์):
- MAIL_HOST=smtp.gmail.com
- MAIL_PORT=587
- MAIL_USERNAME=อีเมลผู้ส่ง
- MAIL_PASSWORD=Google App Password (ไม่ใช่รหัสผ่าน Gmail ปกติ)
- MAIL_FROM=อีเมลผู้ส่ง
เพิ่ม Environment Variables เหล่านี้ใน Railway แล้ว Deploy ใหม่
กรอกอีเมลอาจารย์ในช่องอีเมลของรายวิชา

สำคัญ:
- การสร้าง URL และ deploy ต้องทำผ่านบัญชี Railway/GitHub ของเจ้าของระบบ ฉันไม่สามารถสมัครบัญชี ยอมรับเงื่อนไข หรือกดเผยแพร่แทนเจ้าของบัญชีได้จากในแชต
- ต้องเพิ่ม Volume ให้ถูกต้อง มิฉะนั้นข้อมูล SQLite อาจหายเมื่อ container ถูกสร้างใหม่
- เก็บรหัสผ่านและ App Password ไว้ใน Railway Variables เท่านั้น ห้ามใส่ใน GitHub
- โปรเจกต์นี้เป็นต้นแบบ ควรทดสอบและเพิ่มมาตรการความปลอดภัยก่อนใช้กับข้อมูลนักศึกษาจริง
